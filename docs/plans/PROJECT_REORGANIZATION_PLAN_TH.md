# แผนจัดโครงสร้างโปรเจกต์ให้อ่านและทำงานต่อได้

สถานะ: แผนสำหรับตรวจและลงมือทำ ยังไม่ได้ย้ายไฟล์ตามแผนนี้

## เป้าหมาย

เปิด README แล้วรู้ว่าควรอ่านอะไรตามลำดับ **ข้อมูล → เตรียมข้อมูล → โมเดล → ผลลัพธ์ → เขียนเล่ม** แต่ละขั้นต้องบอกไฟล์เริ่มต้น ผลที่มีอยู่ และงานที่ยังค้าง แยกตำแหน่งของโค้ด ข้อมูล และผลที่สร้างแล้วให้ชัดเจน

งานนี้เป็นการจัดไฟล์และแก้เส้นทางที่เกี่ยวข้อง ไม่เริ่ม training หรือการทดลอง Phase 2 จากการย้ายไฟล์

## โครงสร้างปลายทาง

| โฟลเดอร์ | หน้าที่และที่มาของไฟล์ |
|---|---|
| `src/` | โค้ดระบบหลัก; คงชื่อแพ็กเกจและคำสั่ง CLI เดิม |
| `data/` | ข้อมูล รวม `data_for_project/` เป็น `data/profiles/` และข้อมูลภาพจาก `image_process/` เป็น `data/images/legacy/` |
| `experiments/` | โค้ดและคำสั่งรันการทดลอง; แยกผลที่สร้างแล้วออกไป `artifacts/` |
| `artifacts/` | ผลลัพธ์และโมเดล รวม `train_data/` เป็น `artifacts/training/` และผลทดลองเป็น `artifacts/experiments/` |
| `notebooks/` | Notebook แยก `current/`, `walkthroughs/`, `history/` |
| `docs/` | คู่มือ แผน รายงาน เล่ม บทความ สไลด์ และเอกสาร `thesis_rebuild/` |
| `tools/` | สคริปต์สร้างเอกสาร Excel และงานจาก `pub_multi/` |
| `tests/` | ชุดตรวจสอบโค้ดและเส้นทางหลังย้าย |

สำหรับ `pub_multi/`: ข้อมูลไป `data/publication/`, ผลที่สร้างไป `artifacts/publication/`, เอกสารไป `docs/deliverables/publication/`, และสคริปต์ไป `tools/publication/` รักษาชื่อไฟล์และโครงสร้างภายในชุดหลักฐานเดิมเท่าที่จำเป็นเพื่อค้นย้อนกลับได้

## ลำดับงาน

1. **บันทึกสภาพก่อนย้าย:** เก็บรายการ Git ที่เปลี่ยนอยู่ก่อนงานนี้ พร้อม manifest ตำแหน่งเก่า→ใหม่ ขนาด และ checksum ของไฟล์ข้อมูล โมเดล และผลทดลอง รวมไฟล์ที่ Git ไม่ติดตาม ตรวจชื่อปลายทางชนกันก่อนทำอะไรกับไฟล์
2. **ย้ายทีละกลุ่ม:** เอกสารและเครื่องมือ → notebook → ข้อมูล → ผลทดลอง เก็บชุดหลักฐานที่อ้างอิงกันไว้ด้วยกัน ไม่เขียนทับไฟล์ และลบโฟลเดอร์ต้นทางเมื่อย้ายครบและตรวจว่าว่างแล้ว
3. **แก้เส้นทาง:** ปรับ path กลางใน `src/identity_resolution/settings.py` รวมจุดเรียกใช้ใน Python, notebook, PowerShell, เอกสาร และ `.gitignore` รักษาชื่อและ option ของ `identity-ml`, `identity-full-candidate`, `identity-crm` ไว้
4. **ทำหน้าเริ่มต้น:** README นำทางตามห้าขั้นตอน โดยแต่ละขั้นมีไฟล์สำคัญไม่เกินสามรายการ; `docs/STATUS_TH.md` เป็นสถานะกลาง โดยแยกผลทดลองเดิมออกจากความพร้อมของ Phase 2
5. **ตรวจรับและสรุป:** เปรียบเทียบ manifest และ checksum, ตรวจลิงก์และเส้นทางที่โปรแกรมอ่านจริง, รัน CLI help และ tests ที่เกี่ยวข้องจากหลาย working directory แล้วรายงานไฟล์ที่ย้าย ผลตรวจ และข้อจำกัดคงค้าง

## เกณฑ์ผ่าน

- จำนวน ขนาด และ checksum ของข้อมูล โมเดล และผลทดลองตรงก่อนและหลังย้าย
- ไม่มีเส้นทางเก่าค้างในโค้ดที่ใช้งานจริง; หลักฐานประวัติใช้ตารางตำแหน่งเก่า→ใหม่โดยไม่แก้เนื้อหาที่ถูก hash ไว้
- CLI และ tests ที่เกี่ยวกับ paths/imports/evaluation ผ่าน หรือมีรายการปัญหาเดิมที่แยกจากผลการย้ายได้
- README และสถานะโปรเจกต์พาไปยังไฟล์จริงได้ และอธิบายชัดว่า Phase 1 ผ่านบางส่วน ส่วน Phase 2 ยังไม่เริ่ม

แผนนี้ยังไม่ใช่การรับรองว่าข้อมูลพร้อมใช้ทดลองรอบใหม่ เงื่อนไขทางวิจัยอ้างอิง [ผลตรวจ Phase 1](../research_rebuild/phase_01/06_PHASE_1_READINESS_GATE.md)
