# บทที่ 5 สรุปผลการวิจัยและข้อเสนอแนะ

## 5.1 สรุปผลการวิจัย

งานวิจัยนี้ได้ศึกษาและพัฒนาระบบเชื่อมโยงตัวตนข้ามแพลตฟอร์ม (Cross-Platform Identity Resolution) สำหรับระบบบริหารลูกค้าสัมพันธ์ (CRM) โดยใช้ข้อมูลโปรไฟล์ผู้ใช้จาก Twitter, Instagram และ Google+ รวม 36,804 โปรไฟล์ ระบบถูกออกแบบให้ทำงานเป็นลำดับขั้น ตั้งแต่การลด search space ด้วย exact matching และ blocking ไปจนถึงการให้คะแนนคู่ข้อมูลด้วยแบบจำลอง Machine Learning และการตัดสินใจในระดับ production ผ่าน dual threshold

ตลอดการวิจัย ผู้วิจัยได้ทดลองเปรียบเทียบแบบจำลองหลายชนิดใน 3 สายการทดลองหลัก ได้แก่ สาย Classical Leakage-Safe ที่ใช้คุณลักษณะ 22 ตัว สาย Multimodal Suite ที่ขยายคุณลักษณะจาก 23 ตัวไปจนถึง 41 ตัว และสาย Neural-Network Reference ที่ใช้ IdentityMLP เป็นตัวเปรียบเทียบ ผลการทดลองทั้งหมดอ้างอิงจากข้อมูล split ที่ออกแบบให้ปลอดจาก identity leakage โดยมี component overlap เป็นศูนย์ทุกชุด

จากผลรวมทั้งหมด สามารถสรุปประเด็นสำคัญได้ 4 ประเด็น ดังนี้

ประเด็นแรก ปัญหาหลักของระบบไม่ได้อยู่ที่การเลือกแบบจำลอง แต่อยู่ที่วิธีสร้างคู่ข้อมูล (pair construction) และการแบ่งชุดข้อมูล (split design) หลักฐานที่ชัดเจนที่สุดคือ run ดั้งเดิมที่ให้ค่า AP, AUC และ F1 เท่ากับ 1.0000 ทั้งหมด ซึ่งเกิดจาก identity leakage ไม่ใช่เพราะแบบจำลองมีประสิทธิภาพสูงจริง เมื่อแก้ปัญหา leakage แล้ว ค่า metric จึงลงมาอยู่ในช่วงที่สมเหตุสมผล

ประเด็นที่สอง แบบจำลอง Gradient Boosting เป็นตัวเลือกที่เหมาะสมที่สุดในบริบทของงานนี้ ทั้งในสาย classical ที่ให้ Test AP 0.9703 และ F1 0.9337 ซึ่งเป็นค่าสูงสุดในกลุ่มแบบจำลอง 3 ชนิด และในการเปรียบเทียบ 7 แบบจำลองบน 41 คุณลักษณะ ที่ Gradient Boosting ยังคงนำหน้าด้วย Test AP 0.9797 สูงกว่า MLP ที่ได้ 0.9734 เหตุผลหลักคือ Gradient Boosting สามารถจับปฏิสัมพันธ์ที่ซับซ้อนระหว่างคุณลักษณะกลุ่มชื่อผู้ใช้และชื่อจริงได้ดี ซึ่งเป็นสัญญาณสำคัญที่สุดในงาน identity matching อีกทั้งยังมี feature importance ที่ช่วยให้ตีความผลลัพธ์ได้ง่ายกว่า neural network

ประเด็นที่สาม การเพิ่มหลักฐานเชิงข้อมูลแบบทีละขั้นช่วยยกระดับประสิทธิภาพได้จริง โดย SBERT ช่วยจับความคล้ายเชิงความหมายของ bio ที่ไม่ได้ซ้ำ token ตรง ๆ ทำให้ recall ดีขึ้น และการเพิ่มคุณลักษณะภาพช่วยปรับปรุง AP และ AUC อย่างสม่ำเสมอ แม้จะเป็น incremental improvement แต่แนวโน้มนี้มีความสม่ำเสมอเพราะทุก run ใช้ pair set และ split เดียวกัน

ประเด็นที่สี่ ระบบสามารถนำไปใช้งานจริงในระดับ production ได้ เมื่อใช้ threshold แบบ Exact-First + Dual Threshold ที่ match threshold 0.98 และ review threshold 0.95 ระบบลด search space จาก 449 ล้านคู่เหลือ 2 ล้านคู่ (ลดลง 99.54%) พร้อมยังครอบคลุมคู่จริง 88.67% ผลลัพธ์ปลายทางให้ match precision 0.9550 และรวมโปรไฟล์ได้ 19,799 unified profiles พร้อม lead tiers สำหรับวางแผนการตลาดได้ทันที

### 5.1.1 การตอบวัตถุประสงค์ของงานวิจัย

จากผลการทดลองทั้งหมด สามารถตอบวัตถุประสงค์ของงานวิจัยได้ดังนี้

วัตถุประสงค์ที่ 1 เพื่อศึกษาและพัฒนาระบบเชื่อมโยงตัวตนข้ามแพลตฟอร์มสำหรับระบบ CRM โดยใช้แบบจำลอง Machine Learning ผลการวิจัยยืนยันว่าระบบที่พัฒนาขึ้นสามารถทำงานได้จริงอย่างมีประสิทธิภาพ โดย main run ให้ Test AP ถึง 0.9789 และ F1-score ที่ 0.9340 ซึ่งอยู่ในระดับที่ใช้งานจริงได้ ระบบยังสามารถลด search space จาก 449 ล้านคู่ลงเหลือ 2 ล้านคู่ ขณะที่ยังครอบคลุมคู่จริงได้ถึง 88.67% แสดงให้เห็นว่าการออกแบบ retrieval pipeline ร่วมกับแบบจำลอง Machine Learning สามารถรับมือกับปัญหาขนาดใหญ่ในเชิงปฏิบัติได้

วัตถุประสงค์ที่ 2 เพื่อเปรียบเทียบประสิทธิภาพของแบบจำลองหลายประเภท ผลการเปรียบเทียบชี้ชัดว่า Gradient Boosting ให้ผลดีที่สุดโดยรวม ทั้งในเชิง AP, F1-score และ precision เหนือกว่า MLP, Random Forest, Extra Trees, AdaBoost, Logistic Regression และ Linear SVM สาเหตุหลักเกิดจากแบบจำลองแบบ tree-based สามารถจับปฏิสัมพันธ์ที่ซับซ้อนระหว่างคุณลักษณะต่าง ๆ ได้ดี โดยเฉพาะคุณลักษณะกลุ่มชื่อผู้ใช้ ขณะเดียวกัน MLP แม้จะปรับตัวได้ดีขึ้นเมื่อ feature space ขยาย แต่ยังตามหลัง Gradient Boosting ในทุกมิติหลัก และยังมีข้อจำกัดด้านการตีความผลลัพธ์

วัตถุประสงค์ที่ 3 เพื่อประเมินความเป็นไปได้ในการนำระบบไปใช้งานจริงในระดับ production ระบบผ่านการทดสอบด้วย production thresholds แบบ Exact-First + Dual Threshold ให้ match precision 0.9550 พร้อม review queue 86,296 คู่สำหรับการตรวจสอบด้วยคน และสามารถรวมโปรไฟล์ข้ามแพลตฟอร์มเป็น 19,799 unified profiles พร้อมแบ่ง lead tiers เป็น HOT 4,937 รายการ WARM 9,039 รายการ และ COLD 5,823 รายการ ซึ่งสามารถนำไปใช้ในการวางแผนการตลาดและบริหารลูกค้าสัมพันธ์ได้ทันที

## 5.2 ข้อจำกัดของงานวิจัย

งานวิจัยนี้มีข้อจำกัดสำคัญที่ควรพิจารณาในการตีความผลลัพธ์ ดังต่อไปนี้

1. ข้อมูลที่ใช้มาจาก 3 แพลตฟอร์มเท่านั้น คือ Twitter, Instagram และ Google+ ซึ่ง Google+ ไม่ได้ให้บริการแล้วในปัจจุบัน ทำให้ไม่ทราบว่าระบบจะทำงานได้ดีเพียงใดบนแพลตฟอร์มที่มีลักษณะแตกต่างออกไป เช่น TikTok, LinkedIn หรือ Facebook ที่โครงสร้างข้อมูลและพฤติกรรมผู้ใช้อาจต่างกัน

2. ระบบยังอยู่ในสถานะ partial multimodal เนื่องจากมีเพียง 11.5% ของโปรไฟล์ที่มีภาพ local และ 5.9% ที่มี caption ยิ่งไปกว่านั้นใน test pairs ไม่มีคู่ใดที่มีภาพพร้อมกันทั้งสองฝั่ง ทำให้ไม่สามารถวัดศักยภาพของ full image-to-image matching ได้ในรอบนี้

3. งานวิจัยยังไม่ได้ทดสอบ temporal validation คือการแบ่งข้อมูลตามลำดับเวลาเพื่อจำลองสถานการณ์ที่ผู้ใช้อาจเปลี่ยนชื่อ bio หรือรูปโปรไฟล์ไปตามกาลเวลา ซึ่งอาจส่งผลต่อประสิทธิภาพของระบบในการใช้งานระยะยาว

4. MLP มีลักษณะ black-box และ Gradient Boosting แม้จะมี feature importance ระดับรวม แต่ยังไม่สามารถอธิบายเหตุผลระดับรายคู่ (instance-level explanation) ได้ ซึ่งเป็นข้อจำกัดในการนำไปใช้ในธุรกิจที่ต้องการความโปร่งใสสูง

5. Review queue จำนวน 86,296 คู่ยังเป็นภาระที่ต้องใช้แรงคนตรวจสอบ ซึ่งอาจไม่เหมาะสมสำหรับองค์กรที่มีทรัพยากรจำกัด

## 5.3 ข้อเสนอแนะ

จากผลการวิจัยและข้อจำกัดที่กล่าวมา ผู้วิจัยมีข้อเสนอแนะสำหรับการต่อยอดดังนี้

1. ควรขยายการทดลองไปยังแพลตฟอร์มที่ยังใช้งานอยู่ในปัจจุบัน เช่น TikTok, Facebook หรือ LinkedIn เพื่อทดสอบความสามารถทั่วไป (generalizability) ของระบบ รวมถึงเพิ่มชุดข้อมูลที่มีภาษาไทย เนื่องจากงานนี้ใช้ข้อมูลภาษาอังกฤษเป็นหลัก

2. ควรพัฒนาระบบ full image-to-image matching โดยนำเทคนิค deep learning เช่น contrastive learning หรือ Siamese network มาสร้าง image embedding ที่เปรียบเทียบภาพข้ามแพลตฟอร์มได้โดยตรง ซึ่งจะช่วยเพิ่ม signal สำหรับกรณีที่ข้อมูลข้อความไม่เพียงพอ

3. ควรนำเทคนิค Explainable AI (XAI) เช่น SHAP หรือ LIME มาใช้เพื่อให้สามารถอธิบายเหตุผลในระดับรายคู่ได้ ซึ่งจะช่วยให้ผู้ใช้ระบบ CRM เข้าใจว่าทำไมระบบจึงตัดสินใจ match หรือไม่ match แต่ละคู่ และเพิ่มความน่าเชื่อถือในเชิงธุรกิจ

4. ควรเพิ่มการทดสอบแบบ temporal validation เพื่อจำลองสถานการณ์ที่ข้อมูลผู้ใช้เปลี่ยนแปลงไปตามเวลา ซึ่งจะช่วยประเมินอายุการใช้งาน (shelf life) ของแบบจำลองก่อนที่ต้อง retrain

5. ควรพิจารณาใช้ active learning ในขั้น review queue เพื่อให้ระบบเรียนรู้จากการตัดสินใจของผู้เชี่ยวชาญ (human-in-the-loop) แล้วนำข้อมูลกลับมาปรับปรุงแบบจำลอง ซึ่งจะช่วยลดขนาด review queue ลงได้ในระยะยาว

6. ควรพัฒนาแบบจำลองแบบ hybrid ที่ใช้ neural network สร้าง representation จากข้อมูลดิบ แล้วส่งเข้า Gradient Boosting เป็น meta-learner ในขั้นสุดท้าย เพื่อรักษาทั้งความสามารถในการจับ pattern ที่ซับซ้อนและความสามารถในการตีความผลลัพธ์ไปพร้อมกัน
