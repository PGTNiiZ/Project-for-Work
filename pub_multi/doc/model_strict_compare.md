## Strict Operating Point ที่แนะนำให้ใช้ในรายงาน

หากต้องเลือกผลจากสาย strict no-leak เพียงจุดเดียวเพื่อนำไปเขียนในบทประเมินผล ควรใช้ `logreg + sigmoid @ threshold 0.50` ซึ่งให้ `TP = 986`, `FP = 10`, `FN = 221`, `TN = 461,691`, `precision = 0.9900`, `recall = 0.8169` และ `F1 = 0.8951` เนื่องจากเป็นจุดที่ยังคง recall เดิมไว้ได้ แต่ไม่ทำให้ precision ตันที่ `1.0000` แบบ conservative เกินไป จึงสะท้อน trade-off ของระบบได้สมจริงกว่า

## สรุปสั้น

สิ่งที่ทำให้หลายโมเดลมี precision เท่ากับ `1.0000` ไม่ใช่เพราะโมเดลสมบูรณ์แบบ แต่เพราะใน test split นี้โมเดลไม่ทำนาย false positive เลย หรือมีค่า `FP = 0` ดังนั้นค่า precision จึงตันที่ 1 โดยนิยามของสูตร `TP / (TP + FP)` อย่างไรก็ตาม โมเดลเหล่านี้ยังพลาดคู่ที่ควร match จริงอยู่พอสมควร ดังจะเห็นจากค่า recall ที่อยู่เพียงประมาณ `0.815-0.817`

อีกจุดที่ต้องระวังคือชุด strict test มี class imbalance สูงมาก กล่าวคือมีคู่ลบ `461,701` คู่ แต่มีคู่บวกเพียง `1,207` คู่ เมื่อรวมกับ threshold ที่ค่อนข้างอนุรักษนิยม โมเดลจึงมีแนวโน้มจะทำนาย `MATCH` เฉพาะคู่ที่มั่นใจสูงมาก ทำให้รักษา precision ได้เต็ม แต่ยอมเสีย recall บางส่วนไป

## ถ้าต้องการไม่ให้ precision = 1 ควรทำอย่างไร

หากเป้าหมายคือทำให้ operating point ไม่ conservative เกินไป และไม่ให้ผลลัพธ์ออกมาเป็น `precision = 1` แบบตึงเกินจริง วิธีที่ตรงที่สุดคือปรับ threshold ให้ต่ำลง เพราะตอนนี้หลายโมเดลเลือก threshold ที่ทำให้ทำนายเฉพาะคู่ที่มั่นใจมากมาก เช่น `rf = 0.05`, `extra_trees = 0.04`, `gb = 0.12` และ `logreg = 0.12` เมื่อ threshold ลดลง จำนวนคู่ที่ถูกทำนายเป็น `MATCH` จะเพิ่มขึ้น ซึ่งมักทำให้ recall สูงขึ้น แต่ก็จะเริ่มมี false positives เข้ามาและทำให้ precision ลดลงจาก 1

ในเชิงวิธีวิจัย ไม่ควรเลือก threshold จากเกณฑ์เดียวตายตัวบน validation ที่มี class imbalance สูงมากเท่านั้น แต่ควรทำ threshold sweep แล้วรายงานหลาย operating points เช่น จุดที่ maximize F1, จุดที่ target recall 0.85 หรือ 0.90, จุดที่ target precision 0.95 และจุดที่ควบคุม review queue ให้อยู่ในขนาดที่ยอมรับได้ วิธีนี้จะช่วยให้ผลลัพธ์สะท้อน trade-off จริงของระบบ มากกว่าการได้ค่าตัวเดียวที่ดูดีเกินไป

นอกจากนี้ หากต้องการให้โมเดลต้องเผชิญการตัดสินใจที่ยากขึ้นและลดโอกาสเกิด precision = 1 แบบง่ายเกินไป ควรเพิ่ม hard negatives ให้เข้มขึ้นหรือใช้ test set ที่ยากขึ้นด้วย เพราะถ้าคู่ลบใน test ชัดเกินไป โมเดลที่ conservative จะหลีกเลี่ยง false positives ได้ง่ายมาก การประเมินที่เข้มขึ้นจะทำให้ precision, recall และ confusion matrix สะท้อนความยากของงานได้สมจริงขึ้น

ดังนั้น หากต้องการรายงานผลให้สมเหตุสมผลที่สุด ควรใช้ตารางนี้ร่วมกับ threshold sweep และ confusion matrix เพื่ออธิบายว่าโมเดลไม่ได้ดีที่สุดเพราะ precision = 1 แต่ดีที่สุดเพราะให้สมดุลระหว่าง precision, recall และภาระงาน review ตามโจทย์ของระบบ

สำหรับการวิเคราะห์เชิงลึกเพิ่มเติมว่าค่า precision = 1 เกิดจาก threshold และ calibrated probabilities ที่มีลักษณะกระโดดอย่างไร ให้ดูต่อในเอกสาร `strict_threshold_diag.md` และไฟล์ `strict_threshold_sweep.csv` ส่วนการเปรียบเทียบว่า `isotonic` หรือ `sigmoid` ช่วยให้ operating point สมจริงขึ้นหรือไม่ ให้ดูใน `strict_calibration_compare.md`
